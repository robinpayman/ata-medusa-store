Generate new key in third-party service\n2. Update in Key Vault: `az keyvault secret set --name TRIPLETEX-CONSUMER-TOKEN --value <new-key>`\n3. Restart application (it will fetch new secret)\n4. Verify in logs that new key is being used\n5. Revoke old key in third-party service after confirmation\n\n### For Database Password\n1. Change password in Azure PostgreSQL\n2. Update DATABASE-URL in Key Vault with new password\n3. Restart application\n4. Verify connection logs\n\n## Emergency Response\n\n### If a Secret is Exposed\n1. Immediately rotate the secret\n2. Review Key Vault audit logs to see who accessed it\n3. Check application logs for unauthorized usage\n4. Notify security team\n5. Document incident\n\n### If Key Vault Access is Lost\n1. Verify Managed Identity has permissions\n2. Check Azure RBAC policies\n3. Review Key Vault network rules\n4. Restart application (should retry connection)\n5. If persists, fall back to temporary container env variables (emergency only)\n\n## Security Best Practices\n\n✅ **Implemented**:\n- Secrets never in code\n- Secrets never in .env for production\n- Different secrets for dev/staging/production\n- Managed Identity authentication (no API keys)\n- Audit logging enabled\n- RBAC for access control\n- Caching for performance\n- Proper error messages (don't expose secret names)\n\n✅ **Planned**:\n- Secret rotation procedures\n- Access review quarterly\n- Monitoring and alerts\n- Incident response procedures\n\n## Compliance\n\n### Standards Met\n- [x] 12 Factor App (secrets in environment)\n- [x] OWASP (no hardcoded secrets)\n- [x] PCI DSS (if payment data stored): Secrets in managed vault\n- [x] SOC 2 (if applicable): Audit logging\n\n## Sign-Off\n\n- [x] Code reviewed\n- [x] Documentation complete\n- [x] Security checklist created\n- [ ] Staging environment tested\n- [ ] Production ready\n- [ ] Deployed to production\n\n## Notes\n\n- Development uses .env.local (gitignored)\n- Production uses Azure Key Vault (no local env files)\n- All secrets are non-exportable in Key Vault\n- Managed Identity eliminates need for API credentials\n- Audit logs track all secret access\n\n---\n\n**Next Steps**:\n1.
